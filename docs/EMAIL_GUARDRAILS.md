# گاردریل‌های ارسال ایمیل مرکز (RCHEP)

این سند «دستور همیشگی» ارسال ایمیل مرکز است. هر تغییر در مسیرهای ارسال باید با
این قواعد سازگار بماند. کد گاردریل: `scripts/send_guard.py` — آزمون خودکار:
`python3 scripts/send_guard_selftest.py` (بدون تماس شبکه‌ای، در هر اجرای workflow
پیش از گام ارسال اجرا می‌شود).

## قواعد

| # | قاعده | جای اعمال |
|---|-------|-----------|
| ۱ | **ادعا پیش از ارسال** — نشانهٔ «فرستاده‌شده» پیش از تماس با SMTP ثبت و ذخیره می‌شود؛ اگر ارسال شکست خورد، ادعا «آزاد» می‌شود تا اجرای بعدی بتواند تلاش کند | `send_smtp_email` (دفتر ارسال)، `send_queued_notices` (`sent_at`)، ایمیل خوش‌آمد (`welcome_sent`) |
| ۲ | **یک پیام، یک بار، به یک شخص** — کلید (نشانی + گونهٔ پیام + نشانهٔ رویداد) در بازهٔ خنک‌شدن ۲۴ ساعته فقط یک‌بار پذیرفته می‌شود | `send_guard.reserve()` |
| ۳ | **یک رونوشت برای هر شخص** — نشانی‌های هم‌هویت (نقطه‌های جیمیل، برچسب `+tag`، `googlemail.com`) یکسان‌سازی و یکی می‌شوند | `send_guard.collapse()` در `broadcast_notice` |
| ۴ | **تک‌اجرایی (single-flight)** — دو اجرای همزمان workflow رخ نمی‌دهد | `concurrency.group: email-sync` |
| ۵ | **نشانهٔ یکتای رویداد** — هر سمینار/نشست یک شناسهٔ یکتا (تاریخ + عنوان) دارد؛ Two seminars on one day each get their own email | `data/sent_seminars.json`، `data/notice_queue.json` |
| ۶ | **سقف ارسال در هر اجرا** — پیش‌فرض ۵۰۰؛ بیشتر از آن یعنی حلقهٔ ناخواسته و اجرا متوقف می‌شود | `RCHEP_MAX_SENDS_PER_RUN` |
| ۷ | **آزمون خشک هرگز چیزی را «فرستاده‌شده» علامت نمی‌زند** | `RCHEP_DRY_RUN=1` |
| ۸ | **حریم خصوصی دفتر** — مخزن عمومی است؛ در دفتر ارسال فقط اثر انگشت کوتاه نشانی (sha1 هویت یکسان‌شده) ذخیره می‌شود، نه نشانی خام | `send_guard.fingerprint()` |

## دفتر ارسال

`data/send_log.jsonl` — هر خط یک رکورد:

```json
{"ts": "2026-11-12T10:14:16+00:00", "to": "a1b2c3d4e5f60718", "kind": "notice:هوشواره_1405_آبان_23", "status": "reserved"}
```

`status` یکی از `reserved` (ادعا) یا `released` (شکست ارسال، تلاش دوباره آزاد) است.
واپسین رکورد هر (اثر انگشت، گونه) تعیین‌کننده است: `reserved` تازه = تکراری و مسدود،
`released` = آزاد. پاک‌کردن این فایل به‌معنای «فراموش‌کردن تاریخچهٔ ارسال» است؛ اگر
لازم شد فقط رکوردهای کهنه (بیش از ۲۴ ساعت) حذف شوند.

## فرمان‌های عمدی (بازفرست)

* **بازفرست اطلاعیهٔ یک تاریخ سمینار:** `workflow_dispatch` با ورودی `resend_dates`
  (مثال `1405_آبان_25`). این ورودی گاردریل‌های ۱ و ۲ همان رویداد را کنار می‌گذارد.
* **بازفرست اطلاعیه‌های صف:** ورودی `force_send` = ۱ (متغیر `RCHEP_FORCE_SEND`).
* **اطلاعیه‌ای که پیش‌تر رفته و باید بازفرست شود:** باید `sent_at` آن در
  `data/notice_queue.json` پاک شود (یا با `force_send` اجرا شود).

## متغیرهای محیطی

| متغیر | پیش‌فرض | کار |
|-------|---------|-----|
| `RCHEP_SEND_COOLDOWN_HOURS` | 24 | بازهٔ خنک‌شدن هر (نشانی، پیام) |
| `RCHEP_MAX_SENDS_PER_RUN` | 500 | سقف ارسال در یک اجرا |
| `RCHEP_SEND_LEDGER` | `data/send_log.jsonl` | مسیر دفتر ارسال (برای آزمون) |
| `RCHEP_GUARD_STRICT` | 0 | `1` = اگر ماژول گاردریل بار نشود، ارسال متوقف شود |
| `RCHEP_FORCE_SEND` | 0 | `1` = بازفرست عمدی؛ دفتر ارسال نادیده گرفته می‌شود |
| `RCHEP_DRY_RUN` | 0 | `1` = هیچ ارسال و هیچ ثبت دفتری |

## پیام‌های خطای آشکار

* `Guardrail blocked duplicate: <kind> → x***@domain` — همین پیام پیش‌تر برای همین
  نشانی رفته است؛ ارسال رد شد.
* `Identity guardrail: N duplicate address(es) collapsed.` — نشانی‌های هم‌هویت یکی شدند.
* `SendCapExceeded` — سقف اجرا پر شده؛ احتمال حلقهٔ ناخواسته.
* `WARNING: send guardrails unavailable` — ماژول گاردریل بار نشد (fail-open)؛ با
  `RCHEP_GUARD_STRICT=1` این وضعیت ارسال را متوقف می‌کند.

## نکتهٔ شناخته‌شده: هم‌هویتی انسانی

گاردریل ۳ فقط نشانی‌های هم‌هویت **لفظی** را یکی می‌کند (نقطه/برچسب/دامنهٔ جیمیل).
اگر یک شخص چند حساب مستقل داشته باشد (مثلاً `h.arfaei@gmail.com` و
`arfaeihessam@gmail.com` و `h.arfaei@icloud.com`)، هر سه نشانی مستقل شمرده می‌شوند و
یک اطلاعیه سه بار به صندوق‌های همان شخص می‌رسد. ادغام این نشانی‌ها نیازمند تصمیم
صریح صاحب صندوق است (حذف نشانی از فهرست تأییدشده یا افزودنشان به فهرست
«نام‌های مستعار یک شخص»).
